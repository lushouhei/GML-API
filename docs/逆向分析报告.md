## 一、它是什么（一句话）

把智谱清言 chatglm.cn **网页版的私有接口**，伪装成 OpenAI / Claude / Gemini 三种标准 API，跑在 Cloudflare Worker 上。

本质是 **2API 项目**（web-to-API）—— 不调用官方付费 API，而是拿你的网页登录态去调网页版内部接口。

## 二、核心逆向点：请求签名算法

这是整个项目的技术核心，也是从智谱网页 JS bundle 里挖出来的东西。

智谱网页版给每个 API 请求加了三个头：`X-Timestamp` / `X-Nonce` / `X-Sign`。算法在 `src/chat.ts:228`：

```js
function generateSign() {
  const e = Date.now();                          // 毫秒时间戳
  const A = e.toString();
  const t = A.length;
  const o = A.split("").map(Number);             // 拆成一位一位的数字
  const i = o.reduce((s, v) => s + v, 0) - o[t-2]; // 各位求和，减掉倒数第二位
  const a = i % 10;                              // 取模得校验位
  const timestamp = A.substring(0, t-2) + a + A.substring(t-1, t); // 用校验位替换倒数第二位
  const nonce = uuid(false);                     // 随机 UUID 防重放
  const sign = md5(`${timestamp}-${nonce}-${signSecret}`);
  return { timestamp, nonce, sign };
}
```

**拆解**：

1. **自校验时间戳**：不是原始时间戳，而是把倒数第二位替换成「其余各位之和 mod 10」的校验位。服务端能反推验证 —— 这是一道**低成本反爬门槛**，拦住直接照抄时间戳的脚本小子。
2. **签名盐 `8a1317a7468aa3ad86e997d08f3f31cb`**：硬编码在网页 JS 里的固定值。它**不是你的私人密钥**，是全网通用的公开常量，写进配置文件里没有泄露风险。
3. **MD5**：注意 `src/utils.ts:13` 用的是 `crypto.subtle.digest("MD5")`。**标准 WebCrypto 规范不支持 MD5** —— 这是 Cloudflare workerd 运行时的私有扩展。

> ⚠️ **这直接决定了部署方式**：这份代码**只能跑在 Cloudflare Workers**（或 `wrangler dev` 的本地 workerd 模拟）。想搬到 Node.js / Deno / Docker 需要自己换掉 MD5 实现和 `caches.default` 缓存层。README 没提这点。

### 认证链路

```
你的 chatglm_refresh_token (JWT, 从 Cookie 里抠出来)
        ↓  POST /chatglm/user-api/user/refresh（带签名头）
    access_token (有效期 1 小时)
        ↓  缓存进 Cloudflare Cache API
    POST /chatglm/backend-api/assistant/stream  ← 真正的对话接口
```

另外 `FAKE_HEADERS`（`chat.ts:30`）里塞了整套浏览器指纹：随机 User-Agent 池、`X-App-Fr: browser_extension`、以及一长串 `X-Exp-Groups` AB 实验分组标识（里面能看到 `assistant_model_exp_group:exp:glm4.5`、`mainchat_moe:exp:300` 等内部灰度标记）。

## 三、架构与协议适配

```
客户端(NextChat/Cherry/Claude Code)
    ↓ Authorization: Bearer <你的自定义api_key>
Cloudflare Worker
    ├─ KV 存储：ak:* (API Key 白名单) / rt:* (refresh_token 池)
    ├─ Cache API：access_token 缓存（1 小时）
    ├─ 轮询调度：内存变量 tokenRoundRobinIndex 轮流选 token
    └─ 协议适配层：OpenAI ↔ Claude ↔ Gemini ↔ 智谱 SSE 互转
    ↓ 带签名的伪装请求
chatglm.cn 私有接口
```

**认证与资源分离**的设计还不错：API Key 只管「谁能用」，refresh_token 池只管「用谁的额度」，两者解耦，换账号不用改客户端配置。

### 支持的端点

| 端点 | 协议 |
|---|---|
| `/v1/chat/completions` | OpenAI |
| `/v1/messages` | Claude |
| `/v1beta/models/*:streamGenerateContent` | Gemini |
| `/v1/images/generations` | 绘图（对接智谱绘图智能体） |
| `/v1/videos/generations` | 视频生成（轮询任务状态） |
| `/admin/apikey`、`/admin/token` | 管理接口 |
| `/admin` | 可视化管理面板（HTML） |

## 四、安全审计结果

### ✅ 干净：无后门

对全部 7 个文件做了外部端点扫描（`grep` 所有 `fetch()` 调用和 URL 字面量）：

- **所有网络请求目标只有 `chatglm.cn`**
- 无 webhook、无 telegram bot、无 analytics、无任何第三方上报端点
- 无 `eval()` / `new Function()` 等动态执行
- `atob`/`btoa` 仅用于图片和文件的 base64 编解码

**结论：没有偷你 token 的代码。** 这是这类 2API 项目最需要警惕的地方，此项目通过。

### 🔴 漏洞 1：管理接口鉴权可被完全绕过（已修复）

原代码 `src/index.ts` 三处：

```js
if (env.ADMIN_KEY && adminKey !== env.ADMIN_KEY) {   // ← 问题在这
    return errorResponse("Unauthorized", 401);
}
```

`env.ADMIN_KEY` 为空或未配置时，**整个 if 短路跳过，鉴权形同虚设**。任何知道你 Worker 地址的人都能：

- `GET /admin/apikey` → **拿到你所有 API Key 的明文**，直接白嫖你的会员
- `POST /admin/token` → 往你的池子里塞他自己的 token
- `DELETE /admin/token` → 删光你的 token

README 里轻描淡写为「不推荐用于生产环境」，实际是**默认配置下的静默失效**（fail-open）—— 用户很可能根本不知道自己在裸奔。

**本项目已修复**为 fail-closed：

```js
if (!env.ADMIN_KEY || adminKey !== env.ADMIN_KEY) {  // 未配置密钥 = 直接拒绝
```

### 🟡 风险 2：默认密钥 `changeme`

上游 `wrangler.toml` 里 `ADMIN_KEY = "changeme"`。有值所以会校验，但值人尽皆知，等于没有。本项目的 `deploy.ps1` 加了**部署前拦截**，检测到未修改就直接中止部署。

### 🟡 风险 3：管理密钥明文进 Git

上游把 `ADMIN_KEY` 直接写在 `wrangler.toml` 里，而该文件是要提交到仓库的。本项目已将 `wrangler.toml` 加入 `.gitignore`，只提交 `config/wrangler.toml.example` 模板。

### 🟡 风险 4：CORS 全开

`Access-Control-Allow-Origin: *` 且 `Allow-Headers: *`，管理端点也一样。虽然攻击者仍需知道 ADMIN_KEY，但配合漏洞 1 就是完整的攻击链。修复漏洞 1 后风险可控。

### 🟡 风险 5：轮询索引存在内存里

`tokenRoundRobinIndex` 是 Worker 实例的全局变量。Cloudflare Worker 是**多实例无状态**的，每个 isolate 有自己的计数器，实际负载分配会不均。单账号场景无影响。

## 五、功能真实性核对（README vs 代码）

| README 声称 | 代码实际情况 |
|---|---|
| 支持 glm-4.7 | `/v1/models` 只返回 `glm5`。模型名基本是**幌子** —— 只有 24 位以上字母数字（当作智能体 ID）和含 `think`/`zero`/`deepresearch` 的关键词会真正改变行为，其余一律走网页版默认助手 `65940acff94777010aa6b796` |
| 完整支持 Function Calling | **靠提示词硬凑**。往 system 消息里注入英文指令 + few-shot 示例，教模型输出 `{"tool_calls":[...]}` JSON，再用 `parseToolCalls` 正则解析（含单引号、无引号 key 的容错修复）。流式场景检测到 `{` 开头就缓冲 20 字符再判断。README 自己也承认「可靠性取决于模型对 prompt 的遵循程度」 |
| 适配 claude-code | 基于上一条，**重度工具调用场景预期不稳定** |
| 多账号轮询 | 有，但见风险 5 |
| 部署方式 | 只能 Cloudflare Workers，README 没说明 MD5 的运行时依赖 |

## 六、结论与建议

**可以用，但要清楚它是什么。**

- ✅ **代码无恶意**，架构设计合理，协议适配写得挺完整（3265 行不算敷衍）
- ✅ 适合**个人自用**：把已付费的网页会员接到 Cherry Studio / NextChat 这类聊天客户端
- ⚠️ **不适合**：生产环境、对外服务、重度 Function Calling（如 Claude Code 编程 agent）
- ⚠️ **上游几乎不维护**（1 star，作者明说不修 bug），智谱一改接口就得自己修
- ⚠️ **违反智谱服务条款**，账号有风控/封禁风险

**如果要稳定可用**：花钱上 https://open.bigmodel.cn/ 官方 API，有 SLA、有发票、不担心封号。这个项目的定位是「把已经花过的钱榨干一点」，不是「省下 API 费用」。
